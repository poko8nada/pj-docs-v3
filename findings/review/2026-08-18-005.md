## R-what: Target

- Target: .opencode/skills/skill-sync/scripts/sync.mjs, .opencode/skills/skill-sync/exceptions.json, .opencode/skills/skill-sync/SKILL.md
- Background: skill-sync を2辺（opencode/cursor）から3辺（opencode/cursor/commandcode）に拡張。commandcode の SKILL.md には when_to_use（スキル発動キーワード）がサイド固有フロントマターとして存在し、push 時（→commandcode）は宛先の when_to_use を維持、pull 時（commandcode→他）はストリップする
- Constraints: 上記3ファイルの変更のみ（git diff で取得）。3辺化ロジック正確性、when_to_use の維持/除外、exceptions.json の3辺対応、既存機能退行、SKILL.md ドキュメント整合を検証

## Check (ALL three viewpoints, in order)

- Correctness
  - 3辺 sync ロジック: push は opencode→cursor（null transform）と opencode→commandcode（mergeWhenToUse）の2ペア、pull は cursor→opencode（null transform）と commandcode→opencode（stripWhenToUse）の2ペアを順に処理する。ペア単位で mtime 比較→コピー→サマリ出力を行う構造は正しい。`--skill` フィルタは各ペアの sourceSkills に適用されるため、指定スキルが両ペアで存在する場合は両方にコピーされる。正しい
  - mergeWhenToUse の動作: destText に when_to_use が無ければ srcText をそのまま返す（初回 push 時の安全パス）。src に frontmatter が無ければ srcText をそのまま返す（frontmatter なしスキルの安全パス）。destText に when_to_use があれば、src の frontmatter から既存の when_to_use 行を除外してから dest の値を末尾に追加し、frontmatter を再構築する。正しい
  - stripWhenToUse の動作: frontmatter が無ければテキストをそのまま返す。frontmatter がある場合は when_to_use: で始まる行をフィルタして除去し、残りの行で frontmatter を再構築する。正しい
  - edge case — mergeWhenToUse に空文字 destText を渡した場合（宛先ファイルがまだ存在しない初回 push）: extractWhenToUse は frontmatter が無いので null を返し、srcText がそのまま返される。commandcode に初回 push 時に opencode の when_to_use がコピーされない。正しい（commandcode に既存の when_to_use がなければ、opencode 側の値は不要）
  - edge case — stripWhenToUse に frontmatter なしテキストを渡した場合: splitFrontmatter が head: null を返し、テキストがそのまま返される。正しい
  - edge case — frontmatter のみで本文が無い SKILL.md: splitFrontmatter の正規 /^---\n([\s\S]*?)\n---\n/ は末尾の \n---\n にマッチする必要がある。本文が無い場合でも末尾改行＋--- があればマッチする。正しい
  - isExcluded の振る舞い変更: 旧コードは各サイド固有の例外セットを個別に評価していたが、新コードは Object.values(exceptions).some(...) で全サイドを横断評価する。すなわち、commandcode 側にのみ例外登録されたスキルは opencode→cursor の push でも除外される。これは「サイド別に除外スキルを管理する」という例外機構の意図（ドキュメント記載: "skills that live only on the CommandCode side (never copied to or from the CommandCode directory)"）と矛盾する。旧コードでも実質的に同様の挙動（opencode 側に登録すれば cursor→opencode の pull でも除外）であり、ドキュメントと整合する範囲内的な変化ではあるが、仕様として明示的に確認すべき点である
  - readExceptions の旧配列形式互配: Array.isArray(data) チェックで旧形式を検出し、全3サイドに同一セットを適用する。正しい
  - readExceptions の新オブジェクト形式: Object.keys(SIDES) を使ってサイドを動的に走査し、各サイドの配列を Set に変換する。data[side] が配列でなければ空配列にフォールバック。正しい
  - copySkill の mtime 同期修正: 旧コードでは transform 経由の SKILL.md コピー時に mtime を設定していなかったが、新コードでは全ファイル/ディレクトリで mtime をソースに合わせる。ping-pong 防止の観点から正しい修正。新しいMtime 判定は newestMtime でファイルの mtime のみを走査するため、ディレクトリ自体の mtime 変更は判定に影響しない。正しい
  - ログ出力フォーマット変更: 旧コードは全ペア完了後に1行のサマリを出力していたが、新コードは各ペアごとにサマリを出力する。情報量は増えており、デバッグしやすい。正しい
