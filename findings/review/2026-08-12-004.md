## Check (ALL three viewpoints, in order)

- Correctness
  - ID: C1
  - Severity: high
  - Finding: parseCommands はコマンド区切りとして && / || / ; / | のみを扱い、改行を区切りとして認識しない。`cd /tmp` と `git push --force` を改行で連結したコマンドは 1 セグメントに結合され、split(/\s+/) 後に tokens[0] が `cd` になるため git フラグ検査を素通りする。シェルは改行をコマンド区切りとして実行するため、guard-command を実際に回避できる。
  - Recommendation: 引用符 / 括弧の外にある改行もコマンド区切りとして扱うか、segment を行単位で再分割して各行の git 呼び出しを検査する。`cd /tmp` + 改行 + `git push --force` を deny する回帰テストを追加する。
  - Source: .cursor/hooks/handlers/guard-command.mjs:152-166, 184
  - ID: C2
  - Severity: high
  - Finding: 変数代入で始まるセグメントは /^[A-Z_][A-Z0-9_]*=/ に一致すると、末尾に $() コマンド置換がある場合のみ内側コマンドを返し、`FOO=bar git push --force` のような通常の代入では空配列を返す。このため代入後に続く git コマンドの危険フラグが検査対象から消え、素通りする。
  - Recommendation: 変数代入の接頭辞を除去した残りのトークンを継続して git 検査する（`FOO=bar git push --force` で `git push --force` を検査対象にする）。
  - Source: .cursor/hooks/handlers/guard-command.mjs:176-183
  - ID: C3
  - Severity: medium
  - Finding: BYPASS_PATTERNS に $() コマンド置換のパターンが無く、`git push $(echo --force) origin main`のように置換内に危険フラグを隠すと、トークンは`--force)` となり DANGEROUS_GIT_FLAGS の完全一致検査をすり抜ける。シェルは置換後に --force を展開して実行するため検出を回避できる。
  - Recommendation: `$(` を BYPASS_PATTERNS に追加するか、validateGit でコマンド置換内のトークンも検査対象にする。
  - Source: .cursor/hooks/handlers/guard-command.mjs:9-13, 211
