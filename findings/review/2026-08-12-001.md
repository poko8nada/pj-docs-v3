## Check (ALL three viewpoints, in order)

- Correctness
  - ID: C1
  - Severity: medium
  - Finding: opencode 本体は event フックを fire-and-forget で呼び出す（plugin/index.ts で void hook["event"]?.() として await しない）。そのため idle-runtime.ts の event ハンドラが実行する runIdleChain とフォローアップ送信は opencode run モードではプロセス終了と競合してプロンプトが失われる可能性があり、チェーン内の未捕捉エラーは unhandled rejection になる。
  - Recommendation: フォローアップ送信を event フックに依存せず、可能なら tool.execute.after 等の await されるフックや、run モードではプロセス生存を前提にしない設計（例: 送信前に完了を保証する手段）を検討する。少なくとも runIdleChain 全体を try/catch で包み、エラーを client.app.log に記録する。
  - Source: .opencode/plugins/idle-runtime.ts:66-78
  - ID: C2
  - Severity: medium
  - Finding: フォローアップ送信（client.session.prompt）後にセッションが再び idle になり、エージェントがファイルを編集するとチェーンが再実行されて再びフォローアップが送られる。問題が解消しない限りこのループは続き、繰り返しプロンプトが送信される。ループ回数の上限ガードがない。
  - Recommendation: セッションごとにフォローアップ送信回数や連続実行回数の上限を設け、上限到達時は送信を停止してログに記録する。
  - Source: .opencode/plugins/idle-runtime.ts:77
  - ID: C3
  - Severity: low
  - Finding: prompt 関数内の client.session.prompt の失敗（セッション削除等）が捕捉されず、fire-and-forget の event フックでは unhandled rejection になる。
  - Recommendation: prompt 呼び出しを try/catch で包み、失敗を client.app.log に記録する。
  - Source: .opencode/plugins/idle-runtime.ts:39-44
- Security
  - ID: S1
  - Severity: low
  - Finding: isInsideRoot は path.relative による字句的な判定のみで、シンボリックリンクを解決しない。ルート内のシンボリックリンクが外部を指す場合、外部ファイルが追跡対象となり、drift チェックの STATUS 書き換えや quality チェックの oxlint --fix / oxfmt がルート外のファイルに作用し得る。
  - Recommendation: 追跡判定時に fs.realpath で実パスを解決してから isInsideRoot を適用する。
  - Source: .opencode/plugins/lib/track-files.ts:10-13
